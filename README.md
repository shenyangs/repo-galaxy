# RepoGalaxy

**A GitHub repo, as a galaxy.** Explore actual JavaScript and TypeScript source files as an interactive 2D constellation. Hover to trace imports, select a module to inspect exact paths, and follow resolved imports to another module.

## Run locally

Node.js 22.12+ and npm are required. This project is independent: it does not read files from parent folders, other projects, or user credentials.

```sh
npm install --cache .npm-cache
npm run dev
```

Open http://127.0.0.1:4202. Express listens on `127.0.0.1:5202`; Vite proxies `/api`. Both ports must be free. No API key or model provider is required. The lockfile pins dependencies; use `npm ci --cache .npm-cache` for reproducible installs.

## Three-click demo

1. Click **Load sample**. The included Observatory source is parsed by the API; the screen explicitly shows **EXAMPLE FIXTURE**, 9 modules, and 10 observed edges.
2. Hover and click **App.ts**. The inspector displays `src/App.ts` and its three actual import specifiers.
3. Click **./components/StarMap** in the inspector. It opens `src/components/StarMap.ts` and its three resolved imports.

For public live data, enter `https://github.com/sindresorhus/is` and click **Map repository**. The UI shows **GITHUB LIVE**, the default branch, observed file/edge counts, and whether a size-limited subset or cached result is being shown. Repository contents and counts can change.

## What is real

- Live mode queries public GitHub metadata, the default-branch Git tree, and content-addressed blobs.
- Sample mode reads the actual included files under `fixtures/observatory`; it does not use a precomputed graph.
- TypeScript's source parser observes static `import` and `export ... from` declarations. Only resolved relative imports create graph edges.
- The layout is deterministic Dagre + React Flow, with pan, zoom, directional edges, hover highlighting, and source navigation. It is a 2D graph, not WebGL or 3D.
- **No model inference, AI-generated architecture explanations, or agent events are used or claimed.** This MVP is static source analysis, so model keys are not applicable. The fixture is labeled rather than presented as live GitHub data.

## Limits and safety boundaries

- Only TS/JS static relative imports are resolved. Dynamic imports, CommonJS `require`, path aliases, package resolution, language-server semantics, and non-TS/JS languages are outside this MVP. Imports outside the selected subset remain explicitly unresolved.
- At most 60 files, 100,000 bytes per file, 1,000,000 source bytes total, four concurrent source requests, 12-second per-request timeout, and a five-minute in-memory cache. One live map job runs at a time. GitHub metadata responses are capped at 8 MB and blob responses at 150 KB.
- Public unauthenticated GitHub API access can be rate limited. Rate limits and network errors are visible; **Load sample** is an explicit user choice, never a silent replacement for a failed live request.
- Only strict `https://github.com/owner/repository` inputs are accepted. Outbound requests target `https://api.github.com`; redirects are rejected. No arbitrary local path, private repository credentials, or user source upload is accepted. Fetched code is parsed, never executed.
- Truncated trees and caps may omit modules and edges. This is a navigable source subset, not proof of complete architecture. No production hosting or authentication is provided.
- Live remote repository results are not part of the deterministic automated suite. The saved live smoke confirms one actual request; API failure paths and caps use clearly scoped network mocks in unit tests.
